# 健康生活应用使用说明

“日日有益”是仓库内的独立个人健康网页，和夜班调度器使用不同端口、不同进程；它不会启动 Claude/Codex，也不会调用任何付费模型。

## 当前能做什么

- 保存身高、体重、目标体重、出生年份、活动等级和期望热量缺口。
- 估算 BMI、基础代谢、每日总消耗和保守的每日摄入目标。
- 手动记录饮食、运动消耗和体重，查看当天摄入、消耗、体重与预算余量。
- 把食材分成“绝不吃、不爱但能吃、可接受、喜欢”四档。
- 不联网地生成一份三餐草案；绝不吃的食材和分类会从模板中排除。

照片识别、自然语言自动拆餐、联网营养数据库和条码查询仍在后续阶段；当前的文字说明不会自动变成热量，热量不知道时可以先留空。

## 配置

在数据目录的 `config.json` 增加：

```json
{
  "wellness": {
    "http": {
      "host": "127.0.0.1",
      "port": 8191
    }
  }
}
```

完整形状也可参考仓库的 `config.example.json`。不要把真实域名、口令或密钥写进仓库。

## 启动

```bash
python3 -m nightshift wellness-serve
```

打开 `http://127.0.0.1:8191/health/`。健康数据写到 `$NIGHTSHIFT_HOME/wellness/`；没有设置 `NIGHTSHIFT_HOME` 时，沿用夜班的默认数据目录。

服务默认只监听本机，并且本身不提供登录页。若要挂到公网域名，必须让 nginx/Caddy 等反向代理提供 HTTPS 和访问鉴权，再代理到 `127.0.0.1:8191`；不要把监听地址直接改成 `0.0.0.0` 后裸露公网。

## 数据文件

- `profile.json`：个人档案与目标。
- `preferences.json`：食材偏好与硬约束。
- `entries/YYYY-MM-DD.json`：每天的饮食、运动和体重记录。
- `plans/YYYY-MM-DD.json`：当天生成的餐单。

写入使用文件锁和原子替换。若 JSON 损坏，服务会报错而不是静默清空。当前尚未提供网页导出/删除功能，备份或迁移时应先停服务，再整体复制 `wellness/` 目录。

## 安全说明

所有热量和代谢数字都是粗略估算，不替代医生或营养师。未成年人、孕哺期、慢性病患者、有进食障碍风险的人，或目标 BMI 偏低时，不应依赖自动热量缺口。程序遇到这些标记或异常目标会回退到维护热量并显示提醒。
